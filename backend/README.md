# Unique Network BD Chatbot — Backend

Node.js + Express 5 + better-sqlite3 API. The API stores optional conversation and interaction logs; chatbot answers are generated by the browser's local knowledge engine.

## Local development

```bash
cd backend
npm install
cp .env.example .env
npm start
```

Run tests and apply pending schema migrations:

```bash
npm test
npm run migrate
```

The default local database path is `backend/data/database.sqlite`. Production must set `DB_PATH` to a mounted persistent volume. Never commit the database file or production secrets.

## API routes

| Method | Route | Access |
|---|---|---|
| GET | `/api/health` | Public; SQLite quick-check, migration version and storage metadata |
| POST | `/api/chat-logs` | Public; validated and rate-limited |
| GET | `/api/chat-logs?limit=50&sessionId=...` | Bearer admin key |
| POST | `/api/interactions` | Public; validated and rate-limited |
| GET | `/api/interactions?limit=50` | Bearer admin key |
| GET | `/api/network/status` | Bearer admin key; simulated or allowlisted TCP status |
| POST | `/api/network/connect-test` | Bearer admin key; ephemeral Router TCP or SNMPv2c test |
| GET | `/api/admin/analytics?limit=50` | Bearer admin key; aggregate metrics and unanswered queries |

Chat-log body:

```json
{
  "clientEventId": "event-chat-0001",
  "sessionId": "session-id-123",
  "userMessage": "User question",
  "botResponse": "Local knowledge answer",
  "category": "internet"
}
```

Interaction body:

```json
{
  "clientEventId": "event-int-0001",
  "eventType": "chat_submitted",
  "sessionId": "session-id-123",
  "details": { "source": "web" }
}
```

## Security

- Helmet, exact-origin CORS and 16 KB JSON body limit.
- Allowlisted payload fields; string length and control-character validation.
- API-wide limit: 120 requests/minute/IP.
- Write limits: 30 requests/minute/IP and 12 requests/minute per IP + session key.
- Admin reads require `Authorization: Bearer ADMIN_API_KEY`; comparison uses `timingSafeEqual()`.
- Production startup refuses an absent or shorter-than-32-byte `ADMIN_API_KEY`.
- Rate-limit counters use the process memory store. They reset on restart and are not shared across multiple instances; run one API instance with SQLite.

## Network probe configuration

By default `NETWORK_TARGETS_JSON=[]` returns explicitly marked demo data. To enable real TCP reachability checks, set a server-side JSON array of fixed targets, for example `[{"id":"core-router","label":"Core Router","host":"192.0.2.1","port":8729,"type":"mikrotik"}]`. Supported types: `mikrotik`, `bdcom_olt`, `generic`. Only server-configured targets are probed; the HTTP request cannot supply a host or port. A successful TCP connection proves only that the configured port accepted a connection. It is not RouterOS authentication, ICMP ping, optical RX/TX, or bandwidth measurement. The API intentionally returns no live bandwidth figure until a real device telemetry adapter is implemented.

## Production environment

```env
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
DB_PATH=/var/data/database.sqlite
ADMIN_API_KEY=<at-least-32-random-bytes>
CORS_ORIGINS=https://uniquenetworkbd.github.io
TRUST_PROXY=0
```

Set `TRUST_PROXY=1` only when the hosting platform's network path is confirmed to contain exactly one trusted proxy hop. Incorrect proxy trust can allow spoofed client IPs and weaken IP rate limits.

Generate a secret locally with Node.js:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

Store it only in the host's secret/environment settings. Never place it in `js/config.js`, frontend HTML, or a public repository.

## Persistent storage and SQLite

SQLite runs in WAL mode with foreign keys and busy timeout. Keep the database on a persistent volume and use a single backend instance; do not horizontally scale this SQLite deployment. Back up the database using a SQLite-consistent backup method and test restores before relying on it.

## Frontend connection

Set `window.UNBD_API_BASE_URL` in `js/config.js` to the backend HTTPS origin only (no trailing `/api`). The frontend's bounded localStorage queue retries chat logs when online. If the URL is blank, local knowledge search and local history continue without backend logging.

GitHub Pages serves static files only. It does not host this Node API or persistent SQLite database.


## Router and OLT configuration bridge

The frontend page is available at `layout.html?page=network-config`. It submits a one-time request to `POST /api/network/connect-test`; the backend requires the admin Bearer key, validates literal IP addresses and restricts RouterOS ports to 8728/8729 and SNMP to UDP 161. No device configuration is saved to SQLite or browser storage. Request logging records only method/path/status/latency and never serializes request bodies.

- **MikroTik:** the current implementation tests TCP port reachability only. The submitted username/password are validated in memory, deliberately not transmitted to the router, not logged and not persisted. The response explicitly reports `authentication: not_tested`; this is not a RouterOS API login or model query. Prefer API-SSL on 8729. Port 8728 is unencrypted and should be disabled or restricted to a trusted management network.
- **OLT SNMPv2c:** sends a standard SNMP GET for `sysDescr.0` over UDP/161 and waits up to 4.5 seconds for a response. The current summary reports that an SNMP response was received; it does not yet decode the returned vendor/model string. Community strings are not logged or persisted, but SNMPv2c transmits them without encryption.
- **SNMPv3:** the UI exposes the version choice but returns `not_tested` until security username, security level, authentication and privacy parameters are added. It does not silently downgrade to v2c.

Use only devices and management addresses you administer. This endpoint is admin-authenticated but can initiate outbound probes from the backend network; restrict backend egress/firewall access to the management subnets. The UI clears router password and SNMP community fields after each test attempt. Admin key and all form values remain only in page memory.
